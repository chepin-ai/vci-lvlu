## 四、εcrit(impl) 作为「判定接口最小信息粒度」的联邦映射是否成立？

**结论：不成立（当前形态）。成立需补三件事。**

理由：

**（1）最小信息粒度的定义要求。** 联邦映射意义上的「最小信息粒度」必须是：下游节点仅凭该标量即可复现上游判定的边界行为。即，εcrit(impl) 必须满足——给定 ε ≥ εcrit(impl)，判定为收敛可达；给定 ε < εcrit(impl)，判定为崩坏/不可达。

**（2）当前数据不满足。** 你的 εcrit(impl) 是区间 [0.001, 0.01]（log-stab 上界 0.01、下界 0.001），且：
- 该区间**依赖于实现**（naive vs log-stab 的 εcrit 不同）；
- 依赖于迭代预算与 annealing 制度；
- 区间内行为未扫描，无法定点；
- naive 与 log-stab 的 εcrit 不可通约，故单标量无法同时服务两条实现路径。

因此把 εcrit(impl) 当单一标量做联邦映射，会把「实现 × 制度 × 精度」三维退化成一维，**信息不足**。R-谓词下：**undecided，倾向不成立**。

**（3）成立的最小补全。** 若要把 εcrit 提升为合法最小信息粒度，至少需：

- 定义 εcrit(impl) := sup{ ε : 在制度 Π 下 cost-gap ≤ τ }，其中制度 Π = (精度 p, 迭代预算 N, 收敛阈值 τ, annealing 方案 A, 实现 I)；
- 附带**扫描表**定位点值或给出置信区间；
- 对每个实现 I 给出各自的 εcrit，而非合并；
- 下游使用时必须携带 Π，否则映射失效。

补全后，εcrit(impl, Π) 可作为**制度参数化的最小粒度**成立——但那时它不再是「一个标量」，而是「标量 + 制度签名」。联邦映射能传的是后者，不是前者。
