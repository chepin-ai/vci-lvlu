# LABJUDGE-EXT09 三草案判定

先给结论骨架，再逐案展开，最后总判定。核心争议点我先点明：**②的DONE/BLOCKED边界与"缓存锚≠内容认证"是本轮最可能被制度性滥用的一环；③的"DISPUTED停层"在跨层证据不足时存在停层逃逸风险；①的机器可复核性最强但AC判据需防"证书化=走过场"。**

## 案① CIRC重做立项：主线B见证证书化内嵌A，C仅探针，AC1–AC5

**路线选择：稳健，但"内嵌A"是双刃剑。**
- 主线B（重做）作为唯一推进路径、C降级为探针，避免了上一轮多线并行导致的归因污染。这是正确的收敛。
- 风险点：A被"见证证书化内嵌"，意味着A不再独立提交、只能作为B的附属证据出现。若证书格式由B单方定义，A的原始证据粒度可能被压缩，出现"B自证B"的闭环。

**验收判据机器可复核性：AC1–AC5可复核，但有前提。**
- 若AC定义为：AC1证书schema校验、AC2 B重做前后哈希链连续、AC3 C探针只读且不出现在证书引用闭包、AC4 A证据在证书中可独立寻址、AC5 无B对A的改写权——则全部可脚本复核。
- 隐患：AC3"仅探针"若只定义为"不写入"，机器难以复核"未影响"；必须是**可观测的只读证明**（如C进程无写句柄、C输出不进证书merkle根）。

**制度漏洞：**
- "证书化"若无第三方时间戳/签名锚，B可事后补证。建议AC加一条：证书须由B之外的一方（或至少独立密钥）签署。
- 未见对"B重做失败后C能否升格"的规则——探针是否永久降级？这会成为规避C的通道。

**本案：倾向 pass（附条件），不反对。**

## 案② 缓存锚域限条款：fallthrough DONE四条件 + BLOCKED四触发 + 缓存锚≠内容认证

**这是本轮最危险的一案。路线方向对，但边界设计偏松。**

**"缓存锚≠内容认证"——原则正确，但必须可机器强制。**
- 若只在文档里声明"锚≠认证"，而下游仍以锚命中当认证用，就是纸面原则。
- 可复核要求：锚命中事件与内容认证事件必须是**两个可区分的日志事件类型**，且认证事件不得由锚命中直接派生（无因果边）。否则机器无法区分"声明"与"实际"。

**fallthrough DONE 四条件：**
需检查四点是否都是**机器可判定谓词**：
1. fallthrough发生（可观测事件）——OK
2. 目标域已解析（可判定）——OK
3. **无未决BLOCKED**（关键）——若"未决"定义模糊，DONE会被提前宣告
4. **锚未越权使用**（若定义为"未出现认证派生事件"）——可复核；若定义为"未滥用"，不可复核

漏洞：四条件若允许" silence = 满足"（无日志即视为未触发BLOCKED），则DONE可被**证据缺失**伪造。必须要求**显式否定证据**（如"BLOCKED检查器已运行且返回空"）。

**BLOCKED 四触发：**
- 若四触发是枚举封闭的，则存在"第五种情况"逃逸——既非DONE也非BLOCKED的灰色态。
- 需明确：**fallthrough未DONE且未BLOCKED时状态为何？** 若默认落入DONE，则触发条件形同虚设；若默认落入"挂起"，需有超时与升级路径。

**DONE/BLOCKED边界核心问题：二者是否互斥且穷尽（MECE）？**
- 我判断当前草案倾向于"非BLOCKED即DONE"，这是**制度漏洞**：应改为"仅当四条件全部显式满足才DONE，否则一律非DONE（含BLOCKED/挂起/未知）"。即**默认拒绝**而非默认通过。

**本案：倾向 fail（需修订），我对此案提反对票。**
理由：DONE/BLOCKED边界采用"缺省通过"语义，且"锚≠认证"缺乏机器可强制的因果隔离，存在被下游当作认证锚滥用的结构性漏洞。修订为"显式满足才DONE + 锚/认证事件类型强制分离"后可转pass。

## 案③ A1堆叠升级：L0确权锁边界，L1/L2契约JSON化，DISPUTED停层

**路线选择：层级化正确，但"停让规则"是本轮第二风险点。**

**L0确权锁边界：**
- 正确方向：L0一经确权即锁定，禁止下层回写。可机器复核的关键是**锁的粒度**（锁到字节/字段/记录）。若锁是"声明式"，下层仍可覆盖，则形同虚设。
- 需确认：L0锁是否写入不可变日志（append-only）+ 哈希承诺。否则锁可被静默解除。

**L1/L2契约JSON化：**
- 机器可复核性最高的一环。前提是schema有版本号、必填字段、以及**拒绝未知字段**（否则JSON化只做形式校验）。
- 漏洞：JSON契约若允许 `additionalProperties: true`，则契约化沦为装饰。

**DISPUTED停层——最大漏洞：**
- "停层"意味着争议时停止向更下层传递。问题：**停在哪一层、由谁判定DISPUTED、如何解除？**
- 若DISPUTED由本层自行宣告，则存在**停层逃逸**：下层用DISPUTED阻断升级，规避L0边界检查。
- 可复核要求：DISPUTED必须是**带证据的显式事件**（引用冲突字段+双方契约版本），且停层不得阻断L0确权锁的只读校验。解除需记录裁决者与依据。
- 若停层可"静默继承"（上层DISPUTED自动使下层停），则需防**级联停摆**被当作拒绝服务手段。

**层级停让规则检查：**
- 停让必须**有向、可终止、可审计**。若存在A停让给B、B又停让给A的环，则死锁。
- 建议：停让关系须为DAG，且每层停让事件带序號与超时升级。

**本案：倾向 undecided→pass（附强条件）。**
未到反对票，但DISPUTED停层规则若不定为"显式事件+只读校验不可阻断+DAG停让"，应改fail。
